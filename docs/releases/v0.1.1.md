# Kubeseer v0.1.1

## Highlights

- The versioned Helm OCI chart and `ghcr.io/steeltanuki/kubeseer:0.1.1` controller image provide declarative observation of authorized Kubernetes resources, typed and deterministic status results, validating admission, and runtime access-policy enforcement.
- Release certification now waits for the manager's port-forward to become available before checking `/readyz`. The required end-to-end scenarios still block publication if the package or controller is not ready.
- This patch does not change the Kubeseer API, controller behavior, or chart values schema from the `v0.1.0` source.

## Upgrade considerations

- Install the `0.1.1` chart with its matching `0.1.1` controller image. The release certifies Linux/amd64, Kubernetes 1.35.6 and 1.36.2, and Helm 3.12 or newer.
- The default installation policy denies observed-resource reads. Configure both `installation-access-ceiling` and the manager's observed-resource RBAC before expecting results; users who can read a Kubeseer can also read values published in its status.
- Before upgrading an existing installation, run the documented CRD compatibility check and apply compatible CRDs with an explicit kubeconfig and context. Preserve the intended policy and certificate settings across the Helm upgrade or rollback.
- The default certificate mode requires cert-manager. The `externalSecret` mode requires an administrator-managed serving Secret and public CA bundle. A normal Helm uninstall retains the CRDs, Kubeseer resources, and installation access policy.
