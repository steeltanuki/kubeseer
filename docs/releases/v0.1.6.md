# Kubeseer v0.1.6

## Highlights

- Release checks now validate the tag, source branch, chart version, and release notes before installing build dependencies or starting the product gates.
- CI exercises the image and Helm chart publication flow against a disposable OCI registry, including retries, partial failures, and recovery of missing artifacts.
- Helm chart archives now have normalized metadata so rebuilding the same release candidate preserves its recorded digest across supported Helm versions.
- The controller behavior, Kubeseer APIs, and chart values schema are unchanged; this release improves packaging and release verification.

## Upgrade considerations

- Install chart version `0.1.6` with the matching controller image `ghcr.io/steeltanuki/kubeseer:0.1.6` after the GitHub Release and both public GHCR artifacts are available.
- No application configuration or CRD migration is introduced by these release-pipeline changes. Existing installations can follow the normal chart upgrade procedure and retain their current certificate and access-policy settings.
- A newly created GHCR package may initially be private. If first publication stops after pushing an artifact, make that package public and rerun the same protected tag workflow; the publisher verifies public access before completing the release.
