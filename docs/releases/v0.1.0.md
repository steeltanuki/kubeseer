# Kubeseer v0.1.0

## Highlights

- Kubeseer publishes deterministic, typed status views from built-in Kubernetes resources and structural Custom Resources. A namespaced `kubeseer.io/v1alpha1` `Kubeseer` selects objects, extracts fields with a restricted JSONPath subset, applies predicates and transforms, and computes aggregations.
- Sources can observe authorized namespaces independently. Successful sources and aggregates remain available when a sibling fails; `Ready` and `Degraded` conditions, sanitized reasons, Events, and metrics make the result and its limitations visible.
- The versioned Helm OCI chart and `ghcr.io/steeltanuki/kubeseer:0.1.0` controller image package the two CRDs, validating admission, lifecycle checks, access-policy bootstrap, and webhook certificate support. The released controller image targets Linux/amd64.
- Observation is bounded by the administrator-owned `installation-access-ceiling` policy and Kubernetes RBAC. The controller rechecks authorization at runtime before reading observed resources or publishing a result.

## Upgrade considerations

- The certified environments are Kubernetes 1.35.6 and 1.36.2 with Helm 3.12 or newer. The chart accepts Kubernetes versions from 1.35 up to, but excluding, 1.37; the controller image is certified for Linux/amd64 only.
- The default installation policy denies observed-resource access. Configure both the policy and the manager's observed-resource RBAC before expecting useful results. Anyone allowed to read a `Kubeseer` can read values published in its status, including values observed across namespaces.
- Before upgrading an existing installation, run the explicit CRD compatibility check and apply compatible CRDs using the documented source-checkout procedure with an explicit kubeconfig and context. Preserve intended policy and certificate settings when upgrading the Helm release; apply the same CRD compatibility gate before a rollback.
- The default certificate mode requires cert-manager; the alternative `externalSecret` mode requires an administrator-managed serving Secret and CA bundle. Plan certificate and CA rotation before changing modes or trust material.
- A normal Helm uninstall retains both CRDs, `Kubeseer` resources, and the installation access policy. Removing those resources requires the separate, explicitly confirmed purge procedure.
